# 付款闭环（报销 / 打款流程）

## 流程

```
发起付款/报销申请（支出，勾选「走付款审批流程」）
   ▼
项目成员审批（现有规则：非管理员成员全部同意 / 任一管理员同意）
   ▼
已批准待付款（进入「财务」页的「待打款」）
   ▼  财务执行打款：填实付金额、付款方式
已付款待回单（进入「待补回单」）
   ▼  上传银行回单（报销人或财务均可上传）
已闭环（凭证齐全，closed_at 记录闭环时间）
```

收入侧：登记为「未到账」的收入会出现在财务页「待确认到账」，财务确认后变为已到账；如果还没有凭证，会进入「待补回单」，传完回单即闭环。

## 状态字段（transactions）

| 字段 | 说明 |
|---|---|
| `payment_status` | `pending` 待审批 / `approved` 待打款 / `paid` 待补回单 / `closed` 已闭环 / `rejected` 已驳回 |
| `paid_amount_cents` | **实付金额**（可能 ≠ 申请金额） |
| `paid_at` | 付款/到账时间 |
| `paid_by_user_id` | 执行打款/确认到账的人 |
| `payment_method` | 银行转账 / 现金 / 微信 / 支付宝 / 其他 |
| `closed_at` | 凭证齐全、闭环时间 |
| `reject_reason` | 驳回原因 |

- `settled`（已结算）仍是报表口径：**只有已打款/已到账的交易才计入收入/支出统计**；
- 历史交易 `payment_status` 为空，不参与闭环流程，也不会出现在财务待办里。

## 权限

- **财务权限**：管理员默认拥有；也可以在「用户管理 → 编辑」给普通用户勾选「财务（可打款、确认到账）」。
- 普通用户：可以访问财务页，但**只能看到并补传自己发起**的待补回单。

## 页面

| 页面 | 谁看 | 内容 |
|---|---|---|
| `/finance` 财务 | 管理员/财务 | 待打款、待补回单、待确认到账、最近闭环；可打款/驳回/上传回单/确认到账 |
| `/finance` 财务 | 普通用户 | 只有「我发起的待补回单」+ 上传回单 |
| `/approvals` 待办 | 所有人 | 新增「财务待办」区块（待打款/待补回单/待确认到账），并计入导航铃铛与登录弹窗 |
| 每晚 20:00 短信 | 有手机号的人 | 待审批 + 财务待办合并计算条数（`${n1}`），`${n2}` 取最久一项的小时数 |

## 导出

- `/export/payments.csv`：付款台账（项目/用途/申请金额/闭环状态/实付/方式/付款时间/付款人/闭环时间/回单数/报销人/驳回原因/备注）
- `/export/projects.csv`：项目汇总新增「待打款」「待补回单」两列

## 注意

1. **一笔申请只对应一笔流水**，打款不会新增流水，只把原流水置为已结算，避免重复记账。
2. 勾选「走付款审批流程」时，「已付款」勾选框会隐藏——付款状态由财务打款时记录。
3. 不勾选时保持原来的直接记账方式（历史用法），适合已经付完补记的场景。
